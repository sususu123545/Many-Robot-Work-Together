# 策略服务契约（给训练端 / 模型侧）

真机测试时，模型跑在你的机器上，通过一个 HTTP 接口回答"这一帧该怎么动"。
下面是我们客户端实际会发的报文和期望的回复。**照着实现即可，不需要 ROS**。

## 请求

```
POST http://<你的地址>:<端口>/act
Content-Type: application/json
超时：2.0 s（可用 --timeout 调整）
```

```json
{
  "task": "Pick up the red ball.",
  "stamp": 1795681834.21,
  "state": [-0.046, 0.758, -1.780, -1.273, -0.008, -1.756],
  "image_format": "jpeg",
  "image_b64": "/9j/4AAQSkZJRgABAQ..."
}
```

| 字段 | 说明 |
|---|---|
| `task` | 语言指令，固定为 `Pick up the red ball.` |
| `stamp` | 采集时刻（秒，单调时钟）。只用于日志与延迟统计 |
| `state` | **6 维关节弧度**，顺序 `joint1, joint2, joint3, joint4, joint5, r_joint`。与你训练时 parquet 里的 `observation.state` 同源同单位，直接可用 |
| `image_b64` | 腕部相机 JPEG 的 base64（无前缀）。与训练数据的 `observation.images.camera1` 同一个相机、同一位置 |
| `image_format` | 目前恒为 `jpeg` |

**单位说明**：`state` 与训练数据完全一致（`servo_protocol.to_radians` 的输出，
`r_joint` 以 700 tick 为零点）。请勿自行换算。

## 响应

```json
{
  "actions": [
    [-0.046, 0.758, -1.780, -1.273, -0.008, -1.756],
    [-0.044, 0.742, -1.760, -1.250, -0.008, -1.750],
    …
  ],
  "policy_id": "realkit-t08-003000",
  "control_dt": 0.5,
  "validity_s": 6.0,
  "output_kind": "physical_radians"
}
```

| 字段 | 要求 |
|---|---|
| `actions` | **N × 6**，N = 动作块长度。你设的是 **10**（2 Hz 下 = 5 s）。每行 6 维**关节弧度绝对目标**，与 `state` 同单位 |
| `policy_id` | 任意字符串，写进日志便于追踪是哪版模型 |
| `control_dt` | 每条动作的执行时长（秒）。**请回 0.5**（2 Hz）。我们只接受 0.3~5.0，超出会拒收 |
| `validity_s` | 这一块动作的有效期（秒）。建议 ≥ `N × control_dt`（10 × 0.5 = 5 s），我们给到 6 s 余量 |
| `output_kind` | 必须回 `physical_radians`。若回 `normalized` 会因缺少数据集统计而被拒——归一化请在**你这一侧**完成，对外只输出物理弧度 |

## 我们会做的校验（不通过就拒发，不会"将就着动"）

1. `actions` 每行必须 6 个数字且有限；
2. `output_kind` 必须是 `physical_radians`；
3. `control_dt` 必须在 0.3~5.0 s；
4. 每条动作换算成 tick 后与**当前实际位置**的差不得超过 **100 tick**（单命令机械上限）；
   超限的动作会**等比缩小**（保持方向），而不是逐维截断——逐维截断会把直线路径掰弯；
5. 换算后的 tick 必须落在该关节的机械安全范围内，否则拒收该动作。

## 一个已知的强度差异（请心里有数）

你反馈离线指标里 **joint1/joint2/joint3 略差于"照抄当前状态"**，只有 `r_joint`
（−68%）和 `joint4`（−54%）真正学到东西。真机测试会先跑**影子模式**把这件事量化：
策略在肩/肘/底座上的输出抖动有多大。若确认是噪声，我们会切成
**混合控制**——底座/肩/肘走已验证的脚本下降，**策略只接管 joint4 + r_joint**。
届时会对你的服务提出"只回这两维、其余留空"的变体请求，届时再约定。

## 延迟预算（供参考）

我们实测：图像经隧道取回约 60 ms，网络往返约 40 ms。
你那边 180 ms 推理 + 100 ms 传输 ≈ 280 ms，2 Hz 的 500 ms 预算有 1.8 倍余量。
如果某次响应超过 500 ms，我们会**丢掉这一块并重新请求**（不排队、不追帧）。
