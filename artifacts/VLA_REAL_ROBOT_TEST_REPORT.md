# 真机闭环测试报告（2026-11-28）

模型：`realkit armpi-real-003000`（3000 步，训练集 MAE 0.0159 rad）
机器人：ArmPi Pro 四自由度臂（joint1~4 定位 + joint5 未用 + r_joint 夹爪），2 Hz
结论一句话：**通信与执行链路全部打通并能安全运行，但策略存在逐维系统性偏差，
闭环会把它积分成漂移，目前还不能直接完成抓取。**

---

## 一、通了的部分（可以信任）

| 项 | 结果 |
|---|---|
| 协议一致性 | 请求/响应全部符合契约，`physical_radians` / `control_dt=0.5` / 10 条动作块 |
| 确定性 | 同一观测多次请求返回**完全一致**的动作（跨两天验证） |
| 端到端延迟 | 稳定后 **290~380 ms**（预算 500），中位 355 ms；取图 70~140 ms + 策略 240~430 ms |
| 图像体积 | 22~27 KB（q=70 重编码，640×480 分辨率不变） |
| 指令执行 | 闸门→rosbridge→臂节点→舵机全链路可用，单步验证 joint4 193→204（目标 211，死区吃 6 tick） |

**结论：模型侧不需要改通信方式，现在的接口形态是可行的。**

---

## 二、没通过的部分：逐维系统性偏差

### 2.1 回放验证（关键证据）

把**验证集 episode 8**（模型没见过）下降段的 10 帧，逐帧连同真实图像打给策略服务，
与录制时的动作逐维比对（单位：tick，1 tick ≈ 0.24°）：

| 关节 | 平均偏差 | 符号一致性 | 解读 |
|---|---|---|---|
| joint1 | −0.4 | 100% | 准 |
| joint2 | −5.3 | 88% | 稍多下 |
| **joint3** | **+6.6** | **100%** | **每一步都比演示高 6.6 tick** |
| joint4 | +1.8 | 88% | 接近 |
| joint5 | 0.0 | 62% | 不参与 |
| r_joint | +0.6 | 62% | 无系统偏移，但波动大 |

**关键点：偏差的符号恒定一致。** 这正是单步 MAE 看不出来的失效模式——
平均误差不大（5~7 tick ≈ 1.3°），但每一步都朝同一个方向偏。

### 2.2 闭环里它会积分成漂移

```
每 chunk 10 步 × joint3 +6.6 tick/步 ≈ +66 tick
60 秒内跑 3~4 个 chunk ≈ +30~40 tick 的实际漂移
```

实测（60 秒闭环）：

| 关节 | 起始 | 结束 | 变化 |
|---|---|---|---|
| joint2 | 678 | 643 | −35 |
| **joint3** | **927** | **966 → 继续到 1028** | **+100** |
| joint4 | 198 | 258 | +60 |
| r_joint | 131 | 131 | **从未闭合** |

结果：臂悬在球上方偏后，肘部越伸越高，夹爪始终不开合 —— **不是抓取，是缓慢走偏**。

### 2.3 附带发现：每一步的幅度与舵机死区同量级

该臂舵机死区实测约 **12 tick**（指令 −18，实际移动 11~12）。
策略每步的下发量是 **9~20 tick**，几乎全在死区边缘：

- 一部分指令被死区吃掉 → 状态跟不上；
- 模型看到"没到位" → 下一步继续修 → 又只动一半；
- 表现为振荡（joint2 在 −13/+11 之间摆）。

但**这不是主因**。真正的问题是 2.1 的恒定偏差：即使把节拍降到 1 Hz
（`--stride 2` 实测），振荡依旧，因为方向本身偏了。

## 三、给训练侧的具体建议（按优先级）

### 3.1 逐维检查 joint3 通道（最高优先）

+6.6 tick、100% 同号，很像以下之一：

- 该维的归一化统计量（mean/std）与实际数据不符；
- 预处理/后处理链里该维被做了 ± 翻转或偏移；
- 训练时该维的 action 与 state 用了不同来源。

**验证方法**：取验证集同一帧，把 `observation.state` 与 `action` 一起喂进
`policy_preprocessor` / `policy_postprocessor`，做一次**恒等往返测试**——
若 joint3 往返后不等于原值，就是这里的问题。

### 3.2 报告逐维指标，而不只是整体 MAE

建议在评估里加一列 **"偏差符号一致性"**（sign agreement per channel）。
整体 MAE 会把系统性偏差平均掉，而闭环只看这一列。参考基线：理想应接近随机 50%，
我们测到 joint3 是 100% —— 这一列会立刻暴露问题。

### 3.3 chunk 与节拍

chunk=10（5 s）本身没问题，但建议同时评估 **chunk=4~6**：
开环窗口越短，偏差累积越少。机器人侧我已支持 `--execute-first N` 只执行前 N 步。

### 3.4 数据

当前数据集 9 条全部是"球在正中、20~22 cm"。若要做闭环，建议补：
**横向 ±5 cm 各若干条**（现覆盖仅 ±3 cm），以及**更多条数**。
偏差可能部分来自数据分布过窄。

## 四、机器人侧已做的加固（供参考）

1. **关节范围改用验证过的 jog 包络**（joint3 上限 950 而非舵机表的 1000）——
   今天策略把 joint3 推到 1028，越过 1000 后臂节点**永久锁存**，
   只能靠重启服务（`pose_restore` 直走舵机总线）拉回 1028→915。
2. 目标接近上下限 25 tick 内会打印警告。
3. 单命令 ≤100 tick、超限等比缩小（不逐维截断，否则路径被掰弯）。
4. 抬升/动作后不做乐观判定：影子模式与单步模式始终可用。
