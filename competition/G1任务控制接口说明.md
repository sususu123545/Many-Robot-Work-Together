# G1 雷区与急救物品任务控制

这组模块和原树林演示分开，处理官方简报中的“按顺序拔线，再按清单把用品放入急救包”。它现阶段提供 RGB-D 色块候选识别、任务状态机和仿真/ROS 2/MATRiX 可共用的输入输出接口；不直接输出关节角，也没有宣称 G1 已经会抓取。

## 文件

- `g1_task_perception.py`：只读 RGB、深度图、相机内参，检测配置的 HSV 色块，并换算到机器人基座坐标；在相邻画面间给目标临时跟踪 ID，避免同色顺序重复处理同一目标。不会读 USD 物体标签或世界真值。默认红、黄阈值是场景原型值，必须按比赛相机和现场光照校准。
- `g1_mission_controller.py`：严格按 `wire_color_sequence` 和 `medical_supply_order` 推进；忽略非当前顺序目标，要求连续多帧稳定识别。拔线、抓取、放入只有在执行端回报 `verified: true` 后才计为成功。
- `g1_task_stack.py`：单次调用完成“RGB-D 帧 → 识别候选 → 高层任务命令”，可由 Isaac Sim、ROS 2 或 MATRiX 适配层调用。
- `g1_mission_config.template.json`：留空的配置模板。空序列会拒绝发出动作，必须按赛前裁判公布内容填写；物资类别与药箱也需用相机图像标定。

## 输入输出

`G1TaskStack.update(frame, health, action_result)` 接收 `frame = {rgb, depth, K, seconds}`；`health` 需要包含 `healthy`、`sensor_age_s`、`fallen`、`e_stop`。结果里的 `detections` 是相机识别候选，`mission` 是一条高层动作命令。执行端支持的任务动作为：

- `approach_wire`、`approach_supply`：靠近目标，执行端应继续使用现有 G1 行走策略，并在达到安全操作距离后回报成功。
- `remove_wire`、`pick_supply`、`place_supply`：交给经验证的手部/操作器；成功回执必须带 `verified: true`。拔线可用连接器状态变化确认，抓取可用夹持/视觉确认，放入可用药箱内目标检测确认。
- `hold`、`halt`：不发移动或操作动作。传感器过期、摔倒、急停、超时和未验证操作会锁定在 `halt`，需外部检查后显式调用 `reset_after_external_recovery()`。

执行端回执格式：`{"command_id":"g1-task-0001","status":"running"}`，结束时使用 `status: "succeeded"` 或 `"failed"`。每条命令必须回传原 `command_id`；没有回执不会自动进入下一步。操作成功但 `verified` 缺失或为 false 时立即安全停止，避免重复拔线/抓取。

## 还需实训补齐

官方文件没有写出本队的具体拔线颜色顺序、用品清单、道具 CAD 或操作器控制协议；配置模板因此故意不提供猜测值。当前 USD 中仍是静态道具，G1 模型没有手部操作器；要在 Isaac 中完整演示任务，下一步需要给场景道具加可交互物理约束/状态，再接入带手部的 G1 资产或真实操作器，并把 RGB-D 标定、检测和动作回执放入仿真运行循环。已有的树林完整演示和其源文件保持原样。

## 验证

本地/Isaac Python 均可运行：

```bash
python -m unittest discover -s competition -p 'test_g1_mission_controller.py' -v
```

测试覆盖空配置保持停止、颜色顺序和干扰过滤、连续帧确认、未验证动作安全停止、验证后按序推进、急停/传感器过期、拔线—用品—药箱状态流程，以及合成 RGB-D 色块坐标投影。
