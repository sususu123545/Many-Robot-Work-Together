# G1 第二、三项任务场景

本场景是独立的 Isaac Sim USD，按官方简报第 22 页“雷区侦察 + 收纳急救物品”布置，并按技术文件的人形机器人任务顺序连接树林出口、雷区和急救桌。它不会覆盖或改写现有完整演示场景。

当前开发范围是“不拔线的雷区自主穿越”。场景包含 Unitree G1 29 自由度无手模型、赛道边界、灌木与碎石、5 个红/黄目标和 4 个中性干扰项；急救桌及用品只作为后续场景代理保留。新增导航器消费 RGB-D 建图得到的障碍点和传感器里程计，通过官方 Unitree MJLab 速度策略控制步态；颜色识别只记录红/黄候选，不触发拔线、剪线或抓取动作。树林原演示场景及其源文件没有修改。

场景按赛事资料的雷区与急救任务示意布置。资料没有给出固定颜色序列、物品清单或场地 CAD 尺寸，因此当前不推断具体操作顺序，尺寸只按官方效果图估算。当前导航模式的目标是进入雷区、基于传感器绕开障碍、记录颜色候选并到达雷区出口；拔线及后续物资操作暂不实现。

感知识别文件 `task_logic/g1_task_perception.py` 从 RGB、深度和相机内参检测色块并投影到机器人基座坐标，不查询 USD 标签。`g1_minefield_navigation.py` 只接收传感器估计位姿和 RGB-D 障碍图；`g1_minefield_runtime.py` 把速度请求送入官方 MJLab 步态策略，并把颜色候选写入运行日志。传感器过期、定位数据过期、越界或跌倒时会停止。此模式没有拔线/剪线动作接口。此前的有序操作状态机仍独立留在 `g1_mission_controller.py`，本轮导航运行不调用它。

目前视觉模块只有红、黄原型色阈值，仍需在真实场地光照和机载相机上校准。导航尚未在这台机器的实时 Isaac Sim 预览中验证；单元测试只覆盖局部规划、安全停机和颜色候选算法，不证明整段机器人已跑通。

远程文件：`/mnt/llm/g1_sim_ws/competition_sim/run_g1_minefield_scene.py`

生成单独 USD：

```bash
cd ~/IsaacLab
./isaaclab.sh -p /mnt/llm/g1_sim_ws/competition_sim/run_g1_minefield_scene.py --headless --frames 1
```

输出目录：`/mnt/llm/g1_sim_ws/competition_sim/stages/codex_g1_minefield_medical_20261019/`

渲染预览：

```bash
cd ~/IsaacLab
DISPLAY=:1 XAUTHORITY=/run/user/1000/gdm/Xauthority ./isaaclab.sh -p /mnt/llm/g1_sim_ws/competition_sim/run_g1_minefield_scene.py --preview
```

运行独立雷区自主穿越（按 RGB-D 避障，使用官方 Unitree MJLab 步态，不执行拔线）：

```bash
cd ~/IsaacLab
DISPLAY=:1 XAUTHORITY=/run/user/1000/gdm/Xauthority ./isaaclab.sh -p /mnt/llm/g1_sim_ws/competition_sim/run_g1_minefield_scene.py --preview --g1-minefield-autonomy --g1-policy-source unitree_rl_mjlab --minefield-realtime
```

它会在雷区出口停止并暂停，运行结果写入 `g1_minefield_navigation_result.json`；窗口保持打开供检查，关闭窗口即可退出。

只看机载 RGB-D 颜色候选、不驱动 G1 时，使用 `--preview --rgbd-diagnostics`。空比赛配置让原有操作状态机停在 `WAIT_CONFIG`；雷区穿越模式不调用该操作状态机。
