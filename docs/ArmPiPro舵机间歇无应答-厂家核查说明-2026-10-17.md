# ArmPi Pro 舵机间歇无应答：厂家核查说明

日期：2026-10-17。用途：可转发给商家/厂家，申请正确板卡版本的固件资料。本文尚未发送给任何外部联系人，不包含账户密码或内网连接凭据。

## 可直接发送的说明

您好，我的 ArmPi Pro 在静止状态下读取机械臂舵机的位置、温度时，会间歇出现无应答。希望协助核对扩展板固件的查询转发逻辑，而不是先直接更换设备或刷固件。

商品资料中的扩展板为 **RasAdapter 5A V1.0**，兼容树莓派4B；当前车上实际 PCB 丝印和烧录固件版次仍需对应确认。实物舵机照片可确认有 **LX-225、LX-15D**，夹爪标签疑似 **HTS-16L**（部分遮挡）。软件已从原 ROS 1 迁移至原生 ROS 2，仍按原 Python SDK 的板级 UART 读取格式实现通信；并已用原 SDK 独立只读测试作过对照。

已确认的现象：

1. 大量查询能正确返回，不是完全无法通信。一个运行窗口的 100 条最终读取失败日志分布在全部6个舵机 ID，全部是板级温度查询子命令 **0x09**。各 ID 日志条数分别为 22、17、13、10、21、17；由于在线轮询遇错会提前结束该轮，不能把这些条数直接当作各舵机的故障率。
2. 每次板级查询等200 ms，最多尝试3次。主机端请求示例：`AA 55 05 02 09 02 C0`（ID 2 温度查询）。这里的 `0x09` 是树莓派到扩展板的子命令，不是未经转换即可套用的下游舵机指令。
3. 独占串口、没有 ROS 节点/底盘运动负载的隔离只读测试也可复现；没有两个进程抢同一串口。原厂 SDK 也出现过单次无应答后重试成功，不能据此断定故障仅来自 ROS 2。
4. 一段122.35秒原始串口输入采集中，2880次查询有2次最终失败，均为温度查询。原生解析器、原 SDK 解析器、独立 CRC 扫描器对同一份原始输入都获得2878个舵机回复，内容与顺序一致。
5. 两次失败的约600 ms窗口内，均没有对应 ID/命令的有效回复，但持续收到控制板主动电压遥测。下一次同类请求发出后约2 ms又有回复，不能将下一轮回复误认为上一轮迟到的回复。抓取点是树莓派 Python 串口 API，尚未用逻辑分析仪观测下游舵机线级数据。
6. 温度约28–29℃。一次静止的60轮舵机端电压检查，每个ID各有60个样本，范围如下；没有持续低压证据，但不排除接头瞬态压降，也不是抓取带载供电验收。

| ID | 电压范围 |
|---|---|
| 1 | 8.184–8.228V |
| 2 | 8.184–8.230V |
| 3 | 8.290–8.321V |
| 4 | 8.228–8.275V |
| 5 | 8.268–8.330V |
| 6 | 8.252–8.328V |

7. 相同1秒最小周期下，分别测试“位置→温度”“位置→电压→温度”“位置后延至约40 ms再查询温度”，三组各60轮均出现1次温度最终读取失败。原计划逆序复测因SSH管理通道超时中断，只有前三组记录完整，不能宣称完整重复实验或断定方案间优劣。
8. 树莓派 UART 的累计 overrun 曾显示1，但一次新增舵机故障前后该计数未增长；目前不能将其认定为根因。

**希望提供/确认：**

- 与这块扩展板硬件版次对应的 **MCU固件工程、版本号/变更记录、匹配的板级通信协议**。需要的是板上 MCU 程序，不只是 `ros_robot_controller_sdk.py`，也不是重新刷树莓派系统镜像。
- 板级 `0x09` 温度查询如何映射到下游舵机指令，等待应答时间、收发方向切换、串口/DMA/中断和接收缓冲逻辑分别如何实现。
- 舵机查询是否真实发到总线、是否返回缓存；若未收到舵机应答，控制板应回错误状态还是保持不回包。
- 连续重试同一个 ID/命令是否有忙状态、重复抑制、最小间隔或资源锁限制；混合 LX-225、LX-15D、HTS-16L 是否存在已知查询兼容问题。
- 是否有可用的只读固件版本查询方式、调试日志或官方推荐的独立回读验证方法。
- 如建议更新固件，请先提供硬件适配范围、修复说明、现有版本备份/回退方法和更新风险。暂不在未确认匹配版本前刷写。

所有上述诊断均在机械臂稳固支撑、运动授权关闭条件下进行；没有用反复解除故障、扩大限位/温度门槛或强制运动掩盖通信失败。详细失败查询及原始回包记录可按需提供。

## 当前结论和边界

基础板级协议已有大量成功回读证据，但 **协议时序、MCU固件处理、UART/下游总线与电气原因仍未区分**。现阶段不应盲调查询间隔、直接刷其他 RRC/旧版 RasAdapter 固件，或认定硬件损坏。

下一步需要对应版本的 MCU 源码/协议说明，或在明确接线、电平和测试条件后观测下游总线。拿到资料前不进入抓取实车验收，不解除既有故障锁存。
