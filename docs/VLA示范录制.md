# VLA 示范录制

`tools/record_episode.py` 通过已有 ROS SSH 转发被动订阅，录制期间仅发送
`subscribe`，不发布动作、不调用服务。执行机器人动作仍由独立操作流程负责。

先检查静止采样（在仓库根目录，用现有 Python 环境执行）：

```powershell
python tools/record_episode.py --seconds 10 --kind inspection --instruction "检查静止观测同步"
```

录制完整人工示范时，先启动录制，再用已验收的操作流程执行动作：

```powershell
python tools/record_episode.py --seconds 120 --kind demonstration --instruction "抓起红球并放回原位"
```

默认 ROS 地址是 `127.0.0.1:19091`，图像来自
`/rear_camera/image_raw/compressed`。默认约 5 Hz 图像采样，关节、驱动状态、
臂和夹爪命令、执行回执、底盘速度请求、里程计、急停消息不主动限频。
实际覆盖取决于发布者、ROS QoS、网络和 rosbridge；零计数不能证明未发动作。
这些数据不是完整 ROS bag，不能保证消息零丢失。

每段写入 `datasets/episodes/<UTC时间>/`，已被 Git 忽略，不自动上传：

- `episode.json`：语言指令、用途、主题计数、完整关节消息数、对齐数量和结束原因。
- `events.jsonl`：接收顺序、机器人原始时间戳、电脑接收的单调时钟/墙钟、消息原文。
- `images/*.jpg`：相机原始压缩字节和对应 SHA-256。
- `samples.jsonl`：每张图片关联最近的完整六关节反馈事件编号及时间差。

对齐同时要求机器人消息时间差和电脑接收时间差不超过默认 0.25 秒。
缺少时间戳、反馈不完整、时间偏差过大的图片明确标为不合格，不伪造数据。
这是离线最近邻对齐，可能使用图像之后的反馈；不可以直接充当在线策略输入，
不做插值。重启或时间跳变的采样应单独复核。

`transport_complete=true` 仅表示本次录制循环正常结束，不是传输无丢包保证。
`capture_usable=true` 只表示录到了状态且所有已录图片通过时间对齐检查，
不代表动作覆盖完整、姿态安全或抓取成功。中断或连接异常会保留部分数据，
并将采样标为不完整；没有静默自动重连来掩盖数据缺口。

动作请求和 `/arm_controller/command_result` 分开保存。后者的 `accepted`
也不证明到位，更不证明球已离地。所有录制初始且结束均保持
`outcome=unverified`、`training_ready=false`，包括 `demonstration`。
需要逐段审阅实际离地、保持、放回/释放，以及图像和关节/动作覆盖情况，
再制定动作表示、帧率、归一化和 LeRobot 转换；这里不自动生成成功标签。

局限：HTTP `/frame` 没有可靠源时间戳，因此本工具直接录 ROS 压缩图像；
模型输入尺度和硬件夹爪映射仍需正式标定。合格静止样本只验证采集链路，
不会增加成功抓取示范数量。
