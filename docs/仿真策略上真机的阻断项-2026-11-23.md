# 当前仿真策略为什么不能上实体机

给仿真组的技术说明 · 2026-11-23 · 基于实体 ArmPi Pro（ROS 2 Jazzy）的实测约束

---

## 0. 结论

被评估的是 `lerobot_gazebo_t10_2_camera_corrected` 上训练的 SmolVLA 检查点（3,600 步）。
**它在仿真内部是有效的**（见 §1），下面的问题不是模型质量，而是**仿真与实体之间的数值与物理差异**。

共 **5 条阻断项**，其中 **3 条是硬性安全/功能性否决**，直接下发会损坏设备或必然失败：

| 编号 | 阻断项 | 性质 | 能否靠重训解除 |
| --- | --- | --- | --- |
| B1 | 关节 3 触发软件永久闩锁 | 🔴 安全 | 能（需钳位重采） |
| B2 | 夹爪行程未标定，合不拢 | 🔴 功能 + 安全 | 能（需夹爪标定） |
| B3 | 视觉域差（鱼眼畸变 / 外参偏差） | 🔴 功能 | 部分（需畸变模型） |
| B4 | 任务不同（放粉色圆柱 ≠ 抓红球） | 🔴 功能 | 能（换任务重采） |
| B5 | 帧率 3 倍 | ⚠️ 工程 | 能（抽帧 + 同频训练） |

**在 B1、B2 解除之前，任何形式的关节目标下发都不应进行。**

## 2. 五条阻断项

### B1 · 关节 3 会触发软件永久闩锁（🔴 安全，最高优先级）

**现象**
数据集 `action` 的 joint3 最小值是 **−2.065 rad**。

**证据**
按实体臂的换算关系（中心 500 tick、方向 −1、0.24°/tick）：

```
radians_to_tick("joint3", -2.065) = 500 + (-1) × (-2.065) / 0.00418879 ≈ 993 tick
```

实体臂的真实约束（不是软件窗口 0..1000，而是后果约束）：

- `joint3 > 1000` → arm 节点**永久软件闩锁**，日志出现 `Invalid physical feedback: joint3`，
  **软件无法恢复，只能物理把关节掰回**；
- 关机前必须 ≤ 900，因为断电后关节下垂会额外增加 +29 ~ +118 tick，从 900 掉下去正好越过 1000。

**在实体机上的后果**
仿真最低点对应 tick 993，**距闩锁阈值只剩 7 tick**，距「关机安全线」900 已经**超出 93 tick**。
一旦触发，需要拆机处理。

**对照实测**
2026-11-23 实体成功抓取红球那一次，joint3 全流程只用到 **870 ~ 940 tick**。
仿真策略的需求远超实际任务所需。

**解除条件**
采数据时把 joint3 钳到 **tick ≤ 900，即 rad ≥ −1.6755**，然后重训。
（若必须更深的姿态，需要先在实体上做下落测试确认安全余量。）

---

### B2 · 夹爪行程未标定，两头都不对（🔴 功能 + 安全）

**真机实测（工作台确认，记录于 `tools/gripper_guarded.py`）**

- 全开 ≈ **85 tick**
- 夹爪合拢 ≈ **482 tick**
- **tick 越小 = 开口越大**

**仿真的 r_joint 范围**

数据集 `action` 的 r_joint 为 −2.099 .. −0.999 rad，按 0.18°/tick、中心 700 换算：

```
= 32 .. 382 tick
```

**在实体机上的后果（两个方向都错）**

| 端点 | 仿真 | 真机可用 | 问题 |
| --- | --- | --- | --- |
| 最开 | 32 tick | 全开 85 tick | **超出全开止点 53 tick** → 顶死，堵转发热 |
| 最闭 | 382 tick | 合拢 482 tick | **距合拢差 100 tick** → 夹爪永远合不拢，抓不住任何东西 |

也就是说：**即使 B1 解决了，这一版模型下到实体也抓不住球**，因为它的「闭合」在真机上只是半闭。

**解除条件**
仿真里 r_joint 的实际行程必须落在 **85 .. 482 tick** 内，或者由实体方先给出「开口 ↔ tick」标定曲线，
仿真按该曲线采样。当前仿真的夹爪几何与实体并未做过这一标定。

---

### B3 · 视觉域差（🔴 功能）

**真机相机**

| 项目 | 值 |
| --- | --- |
| 型号 | Nuwa-HP60C（腕部安装） |
| 模型 | **equidistant 鱼眼**（不是 pinhole） |
| K | `[541.286, 0, 308.972; 0, 536.832, 220.808; 0, 0, 1]` |
| D | `[-0.17327, 0.27697, -1.97373, 3.56887]` |
| 重投影 RMS | 1.158 px |
| 分辨率 | 480 × 640 |

**仿真侧**

- 渲染图，**没有畸变模型**；
- `camera_joint` 是 **fixed** 关节，挂在 `link4`（前臂）上，
  origin `xyz = 0, -0.042169, 0.046483`，rpy 全 0 —— 挂载位置与真机一致（都在腕部）；
- 但这是 **URDF 名义外参**，而实体手眼标定结果与 URDF 在 **z 方向差 21.8 mm**（实体以手眼为准）。

**后果**
同样的像素在两边指向不同方向；鱼眼畸变在画面外围最大，而抓取时目标通常出现在画面下半部边缘。
外参 21.8 mm 的偏差在 20 cm 工作距离上约为 6° 的方向误差。

**解除条件（任选其一）**

1. 仿真渲染接入真机的 `K` + `D`（equidistant 模型）与手眼实测外参；或
2. 承认这条跨不过去，改由**实体数据微调**，仿真只用于接口验证。

**⚠️ 需要仿真组确认**：仿真相机的视场角、内参、是否有 letterbox/pad、`resize_imgs_with_padding` 之后
实际送入网络的分辨率（当前配置是 512×512）。

### B4 · 任务不同（🔴 功能）

| | 仿真 | 实体目标 |
| --- | --- | --- |
| 指令 | `Place the pink cylinder in the left target zone.`<br>`Place the pink cylinder in the right target zone.` | 抓取地面红色小球 |
| 物体 | 粉色圆柱（直径 39 mm、高 34 mm 量级） | 红色小球（直径约 35 mm） |
| 动作 | 抓 + 搬运 + 放到目标区 + 释放 | 抓取 + 抬升 |

**后果**
模型没有「红球」这个概念；语言指令也不在分布内；粉圆柱与红球在颜色、形状、反光上都不同。
直接下发等于要求模型做零样本任务迁移。

**解除条件**
按红球抓取任务重采重训，或明确这版 checkpoint 只用于接口/管线验证，不作为可执行策略。

---

### B5 · 帧率差 3 倍（⚠️ 工程，**可解**）

- 数据集 **10 fps**；实体总线一条命令 **0.3 ~ 5.0 s**，指令率上限 **1/0.3 = 3.33 Hz**。
- 差值 **3 倍**。

**这一条是可以解决的**，因为每个动作维度都是**绝对关节位置**（不是增量）：
每 3 步取 1 个即可，几何不变，只稀疏路点。50 步的 chunk 抽帧后是 17 个路点、约 5.1 s。

**但闭环必须同频。** 用 10 fps 训练、按 3.33 Hz 执行，策略每次看到的状态跳变会是它预期的 3 倍——
这才是真正的失配。所以演示要么按 3.33 fps 采，要么在转换时降采样并在训练时保持一致。

## 3. 已经确认"通"的部分（不需要改）

- **关节顺序完全一致**：`joint1, joint2, joint3, joint4, joint5, r_joint`；
- 仿真与实体共用 `armpi_pro_description`，**六轴弧度可以直接用 `spec.radians_to_tick()` 换算**，
  不需要额外的坐标变换；
- 除 joint3 与夹爪外，其余四轴都稳稳落在实体窗口内：

| 关节 | 仿真弧度 | 换算 tick | 实体窗口 | 余量 |
| --- | --- | --- | --- | --- |
| joint1 | −0.323 .. 0.323 | 423 .. 577 | 0 .. 1000 | 423 ✓ |
| joint2 | −0.863 .. 0.008 | 294 .. 502 | 125 .. 875 | 169 ✓ |
| joint3 | −2.065 .. −0.490 | 617 .. **993** | 0 .. 1000（且须 ≤900） | **−93 ✗** |
| joint4 | −0.884 .. 0.075 | 289 .. 518 | 0 .. 1000 | 289 ✓ |
| joint5 | 0 .. 0 | 500 | 0 .. 1000 | 500 ✓（全程未动） |
| r_joint | −2.099 .. −0.999 | 32 .. 382 | **85 .. 482** | **−53 / +100 ✗**（见 B2） |

> 余量的算法：joint1~joint5 相对舵机窗口 0..1000（joint3 另加 900 的安全线），
> r_joint 相对**可用区间 85..482**（不是舵机窗口 0..700，那个窗口允许把夹爪顶死）。
> 表中两个数字分别是「最开端」与「最闭端」的余量，任一为负即判不合格。

**所以问题不在坐标系，而在数值范围的物理语义没有对齐。**

## 4. 需要仿真组提供 / 确认的清单

| # | 事项 | 用途 |
| --- | --- | --- |
| 1 | joint3 在采集与训练中钳位到 ≤900 tick | 解除 B1 |
| 2 | r_joint 行程对齐 85..482 tick，或提供夹爪标定曲线 | 解除 B2 |
| 3 | 仿真相机内参 / 视场角 / 是否带畸变模型 | 判断 B3 能否解除 |
| 4 | 是否使用手眼实测外参（而非 URDF 名义值） | 同上 |
| 5 | 采集帧率能否改为 3.33 fps | 解除 B5 |
| 6 | 在 Gazebo 中做一次闭环 rollout（当前模型） | 目前**没有任何任务成功率**数据 |
| 7 | 是否接受「仿真只做接口验证、策略由实体数据微调」的路线 | 决定后续分工 |

---

## 5. 实体侧会做的对应防护

即使上述解除，实体侧在下发前仍会加三道钳位，**这三道不是可选项**：

1. `joint3` 目标强行钳到 ≤ 900 tick；
2. `r_joint` 目标钳到 85 .. 482 tick；
3. 单条命令行程 ≤ 100 tick、时长 0.3 ~ 5.0 s，且运动许可默认关闭，需显式授权。

## 6. 复现方式

```bash
# 动作范围 → 实体 tick 的安全性检查（纯 Python，无需 GPU / ROS / 机器人）
python3 tools/check_sim_action_transfer.py \
  --stats artifacts/smolvla_sim_finetune_20261123/sim_dataset_stats.json \
  --out   artifacts/smolvla_sim_finetune_20261123/action_transfer_check.json

# 离线评估（含「原地不动」基线）
python3 tools/eval_smolvla_offline.py --checkpoint <ckpt>/pretrained_model \
  --dataset-root <...>/lerobot_gazebo_t10_2_camera_corrected \
  --episodes 3,13 --samples 64
```

数据集 `stats.json`、检查报告、训练曲线与两份评估报告都在
`artifacts/smolvla_sim_finetune_20261123/`。
