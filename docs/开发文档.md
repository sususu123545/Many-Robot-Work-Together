# 多机器人协作服务系统 - 开发文档

## 1. 文档概述
本文档面向系统开发人员、维护者及贡献者，详细说明多机器人协作服务系统的软件架构、模块设计、接口定义、通信机制、编译构建流程及扩展方法。系统基于 ROS 2 Humble，采用主从式架构，实现室内服务任务的自动调度与执行。

## 2. 系统架构设计

### 2.1 整体架构分层
系统分为四层：
- **用户交互层**：Web 前端（React/Vue），提供任务输入、状态展示、急停控制。
- **服务接入层**：后端服务（FastAPI/Node.js），负责 HTTP/WebSocket 连接、任务解析、会话管理。
- **决策调度层**：主机器人节点，运行 SLAM 建图、全局地图维护、任务队列管理、机器人状态监控与任务分配。
- **执行层**：工作机器人节点，执行导航、视觉抓取、物品放置、状态上报。

### 2.2 模块划分
| 模块名称 | 功能 | 实现技术 |
|---------|------|----------|
| web_frontend | 用户界面 | React + ROSLIBJS |
| backend_service | 任务 API、状态推送 | FastAPI + WebSocket |
| master_robot | 建图、调度、监控 | ROS 2 节点（Python/C++） |
| worker_robot | 导航、感知、抓取 | ROS 2 节点 + MoveIt + YOLO |
| common_lib | 消息定义、工具函数 | ROS 2 接口（.msg/.srv/.action） |

### 2.3 部署拓扑
- 主机器人和工作机器人均运行 Ubuntu 22.04 + ROS 2 Humble，通过 WiFi 连接同一局域网。
- 后端服务可运行在主机器人上或独立服务器。
- 网页前端通过浏览器访问后端服务。

## 3. 模块详细设计

### 3.1 主机器人模块
#### 3.1.1 建图与定位
- 使用 SLAM Toolbox 构建 2D 栅格地图，支持实时更新。
- 通过 `/map` Topic 发布地图，频率 1 Hz。
- 定位采用 AMCL，融合里程计和激光雷达数据。

#### 3.1.2 任务调度器
- 维护全局任务队列（`TaskQueue`），每个任务包含：`task_id`, `type`, `pick_position`, `place_position`, `object_name`, `status`, `assigned_robot`。
- 调度策略：轮询或基于机器人电量/距离的代价函数。
- 通过 `/task_assignment` Service 分配任务，返回分配结果。

#### 3.1.3 监控与异常处理
- 订阅所有工作机器人的状态 Topic（`/robot_status`），包含电量、位置、当前任务、错误码。
- 实现心跳检测，超时（5 秒）触发重连机制。
- 碰撞检测通过工作机器人上报的 `/emergency_stop` 信号处理。

### 3.2 工作机器人模块
#### 3.2.1 导航
- 使用 Nav2 的 `nav_to_pose` Action，接收目标坐标（map  frame）。
- 支持动态避障，局部规划器为 TEB 或 DWB。

#### 3.2.2 视觉抓取
- 深度相机（Intel RealSense D435）发布 RGB 和深度图像。
- YOLOv8 检测目标物体，输出边界框和类别。
- 根据深度图计算目标 3D 位置（相机坐标系），转换到机械臂基座坐标系。
- MoveIt 2 规划抓取轨迹，通过 `/grasp` Action 执行夹爪闭合。

#### 3.2.3 状态机
工作机器人内部使用状态机管理执行流程：
- IDLE → NAV_TO_PICK → DETECT → GRASP → NAV_TO_PLACE → PLACE → COMPLETE。
- 每个状态超时（如导航超时 60 s）触发错误恢复。

### 3.3 后端服务模块
- **任务解析**：将用户文本通过关键词匹配或简单 NLP 转换为结构化任务（物品、目标位置预定义）。
- **WebSocket 连接**：与前端保持双向通信，推送实时状态（机器人位置、任务进度）。
- **REST API**：提供 `/api/task`（POST 提交任务）、`/api/status`（GET 获取全局状态）、`/api/cancel/{task_id}`（取消任务）。

## 4. 通信协议与接口定义

### 4.1 ROS 2 Topic
| Topic 名称 | 消息类型 | 发布/订阅 | 说明 |
|-----------|---------|----------|------|
| `/map` | `nav_msgs/msg/OccupancyGrid` | 主→工作 | 地图数据 |
| `/robot_status` | `custom_msgs/msg/RobotStatus` | 工作→主 | 电量、位置、状态码 |
| `/task_feedback` | `custom_msgs/msg/TaskFeedback` | 工作→主 | 当前任务进度（百分比） |

### 4.2 ROS 2 Service
- `/master/assign_task`（`AssignTask.srv`）：主机器人分配任务给指定工作机器人。
- `/worker/report_result`（`ReportResult.srv`）：工作机器人上报执行结果（成功/失败及原因）。
- `/master/emergency_stop`（`Trigger.srv`）：触发全局急停。

### 4.3 ROS 2 Action
- `/worker/navigate`（`NavToPose.action`）：导航到目标点。
- `/worker/grasp`（`GraspObject.action`）：执行抓取，返回成功/失败。

### 4.4 Web 通信
- 后端暴露 WebSocket 端点 `/ws/status`，前端订阅获取实时状态 JSON。
- HTTP POST `/api/task` 请求体示例：
```json
{
  "command": "拿一杯水",
  "user_location": {"x": 2.5, "y": 3.0}
}
```

## 5. 数据流与关键流程

### 5.1 任务下发数据流
1. 用户输入 → 前端封装 JSON → 后端解析 → 转换为内部任务对象（包含取物点、送达点、物品名）。
2. 后端通过 ROS 2 Service（`/master/assign_task`）发送给主机器人。
3. 主机器人选择工作机器人，通过 Action（`/worker/navigate` 和 `/worker/grasp`）下发子任务。
4. 工作机器人执行并实时发布 `/task_feedback`，主机器人汇总后通过 WebSocket 推送前端。

### 5.2 地图更新数据流
- 主机器人 SLAM 更新地图 → 发布 `/map` → 工作机器人订阅并更新本地成本图。
- 若地图发生变化，主机器人会重新发送完整地图，工作机器人调用 Nav2 的 `map_server` 重载。

### 5.3 异常处理数据流
- 工作机器人检测到碰撞 → 发布 `/emergency_stop` → 主机器人接收后广播所有机器人暂停，并发送 WebSocket 警告。
- 工作机器人电量低于阈值 → 在 `/robot_status` 中标记 → 主机器人将其踢出任务队列，并调度充电（发送导航到充电桩指令）。

## 6. 部署与配置

### 6.1 环境变量与配置文件
- 所有 ROS 节点使用 YAML 参数文件：
  - `master_params.yaml`：地图保存路径、调度策略、心跳超时时间。
  - `worker_params.yaml`：机器人命名空间、相机参数、抓取偏移量、充电桩坐标。
- 后端服务配置：`config.json`，包含端口、ROS 桥接地址、允许的 CORS 源。

### 6.2 多机器人命名空间
- 每个工作机器人启动时设置 `robot_name` 参数（如 `worker1`），所有 Topic 和 Action 自动添加前缀（如 `/worker1/navigate`），避免冲突。

### 6.3 网络配置
- 建议使用静态 IP 或 mDNS，主机器人 IP 固定。
- ROS 2 环境变量 `ROS_DOMAIN_ID` 统一设为相同值（如 42），确保通信正常。

### 6.4 启动顺序
1. 主机器人（建图节点 + 调度节点 + 后端服务）
2. 工作机器人（每个单独启动）
3. 前端（开发模式或静态部署）

## 7. 开发环境搭建

### 7.1 依赖版本
- ROS 2 Humble（对应 Ubuntu 22.04）
- Python 3.10，C++17（用于性能关键节点）
- OpenCV 4.5+，PyTorch 1.13+（YOLO 推理）
- Node.js 18+，npm 9+
- FastAPI 0.95+，Uvicorn

### 7.2 开发工具
- VS Code + ROS 插件，或 CLion。
- 使用 `colcon` 构建，`ament_cmake` 和 `setuptools` 混合。
- 代码格式化：`black`（Python），`clang-format`（C++）。

### 7.3 模拟环境
- 使用 Gazebo Ignition 或 Webots 进行无硬件仿真。
- 提供 `bringup_sim.launch.py`，加载虚拟机器人、激光雷达和相机。

## 8. 测试策略

### 8.1 单元测试
- Python 使用 `pytest`，C++ 使用 `gtest`，测试核心算法（路径代价、抓取点计算）。
- ROS 2 节点测试使用 `launch_testing`。

### 8.2 集成测试
- 模拟主从通信测试：使用 ROS 2 的 `test_msgs` 和 `test_nodes`。
- 端到端测试：使用 `requests` 库模拟前端调用 API，验证任务全流程。

### 8.3 硬件在环测试
- 在真实机器人上逐步测试导航、视觉、抓取，记录成功率。
- 提供日志分析工具（`ros2 bag` 记录所有 Topic）。

## 9. 扩展指南

### 9.1 新增任务类型
- 在 `common_msgs/msg/Task.msg` 中添加新的 `type` 枚举。
- 修改主机器人的调度逻辑，匹配新类型对应的取放点获取方式。
- 更新后端任务解析器，支持新指令。

### 9.2 添加新的工作机器人
- 确保新机器人具有相同硬件接口。
- 复制 `worker_bringup.launch.py`，修改 `robot_name` 和 IP。
- 主机器人自动发现新机器人（通过 ROS 2 的 `node_discovery` 或手动配置列表）。

### 9.3 更换视觉模型
- 替换 YOLO 权重文件路径，保持输出格式一致。
- 修改 `detection_node` 中的类别映射文件。

### 9.4 集成大语言模型
- 在后端添加 LLM API 调用（如 GPT），将用户自然语言解析为结构化任务。
- 修改 `task_parser` 模块，优先使用 LLM，失败时回退关键词匹配。

## 10. 性能优化建议
- 地图压缩：使用 `map_compression` 插件减少传输带宽。
- 任务缓存：主机器人缓存静态物体位置，减少重复视觉识别。
- 并行导航：工作机器人之间通过主机器人的路径碰撞避免算法（如时间窗）。

## 11. 常见问题及调试

| 问题 | 可能原因 | 解决方法 |
|------|---------|----------|
| 工作机器人无法接收地图 | ROS_DOMAIN_ID 不一致 | 统一设置为相同值 |
| 抓取位置偏移 | 相机外参未标定 | 执行手眼标定，更新变换矩阵 |
| 后端无法连接 ROS | rosbridge 未启动 | 确保 `rosbridge_websocket` 节点运行 |
| 网页无实时状态 | WebSocket 断开 | 检查后端日志，防火墙开放端口 |
