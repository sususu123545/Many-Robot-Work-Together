# 关机后恢复 —— 三步清单

> 适用：ArmPi Pro 任务控制台（`robot_console.html` + 本地代理 `proxy_server(1).py`）

---

## ① 电脑侧（每次开机都要做）

**双击 `启动控制台.bat`**，它会自动：

1. 启动本地代理 `127.0.0.1:8000`（如果已经在跑就跳过，不会重复启动）
2. 打开浏览器到 `http://127.0.0.1:8000`

### 不想用脚本的话，手动也是两步

```bat
cd /d D:\多车协作
"C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe" "proxy_server(1).py"
```

然后浏览器地址栏输入 `http://127.0.0.1:8000` 回车。

> ⚠️ **不要双击 `robot_console.html`**。`file://` 协议下页面取视频会跨域失败，必须经本地代理走 `http://127.0.0.1:8000`。
>
> 代理窗口可以最小化。关掉那个黑窗口就停了代理。

---

## ② 页面里（3 步）

1. **「小车 IP」**填当前地址（例如 `10.120.150.178`）→ 点 **「连接」**，左上角变绿点即成功
2. **「画面源」**选 **深度相机RGB /ascamera_hp60c/rgb0/image**
3. 画面若暂时是黑的：它会**每 3 秒自动重试、最多 5 次**，等相机节点起来会自己出现。
   也可以**点一下画面**强制刷新。

---

## ③ 小车侧（只有小车也重启过才需要）

> 🗺️ **先搞清"三层"，后面就不会敲错地方**
>
> | 层 | 怎么到这一层 | 提示符长什么样 | 这一层能干什么 |
> |---|---|---|---|
> | ① **你的 Windows 电脑** | 开机后就在这一层 | `C:\Users\Administrator>` | 双击 bat、开浏览器、发 ssh、`ping` |
> | ② **小车的宿主系统**（Pi / Debian） | `ssh pi@<小车IP>` 进来（密码 `raspberrypi`） | `pi@raspberrypi:~$` | `ps` 看进程、`docker exec`、`vcgencmd` |
> | ③ **小车里的 Docker 容器** `armpi_pro` | 靠 `docker exec … armpi_pro …` 进去 | 不常驻，一般一条命令进出 | ROS 节点都在这一层跑 |
>
> ⚠️ **三层的命令不能混着敲**，层次不对会报 `command not found` 或"找不到容器"。

小车**重启后 IP 会变**。先在**电脑上**（①层）执行这条查新 IP：

```bat
ping raspberrypi
```

能解析出 IP 就说明它在这个网络里。然后启动**深度相机节点**（它是手动启动的，不在开机自启链条里，重启就丢）。
这条命令在**电脑上**（①层）直接执行即可，它会自己 ssh 进去、再 `docker exec` 到容器里：

```bat
ssh pi@<小车IP> "docker exec -d -w /home/ubuntu armpi_pro bash -lc 'bash /home/ubuntu/run_ascam_hp60c.sh > /tmp/ascam_run.log 2>&1'"
```

- 密码：`raspberrypi`（**输入时屏幕不显示任何字符**，这是正常的）
- 回车后**没有输出、直接回到提示符** = 正常（`-d` 是后台分离运行）
- 等 5~8 秒，页面画面就会出现

### ③-b 启动激光雷达（小车重启过才需要）

雷达节点也是**手动启动**的，重启就丢。在**电脑上**（①层）一条命令：

```bat
ssh pi@<小车IP> "docker exec -d -w /home/ubuntu armpi_pro bash -lc 'bash /home/ubuntu/run_ld06.sh > /tmp/ld06_run.log 2>&1'"
```

- 同样**没有输出 = 正常**；等 5 秒左右雷达话题就绪
- 脚本是**幂等**的——重复执行安全（会先清掉旧实例再启动）
- 验证（②层）：

```bash
docker exec armpi_pro bash -lc 'source /opt/ros/noetic/setup.bash; export ROS_MASTER_URI=http://raspberrypi:11311; timeout 6 rostopic hz /scan'
```

看到 `average rate: 10.0` 左右就成功了。
⚠️ 数雷达进程别用 `pgrep -x ldlidar_stl_ros_node`（进程名被 Linux 截断到 15 字符，永远匹配不上），
用 `pgrep -f "[l]dlidar_stl_ros_node"`。

> 🔌 **雷达接线备查**（LD06 → FT232RL 转接板）：`P5V→5V`、`GND→GND`、**`DAT→RX`**（数据是雷达发出来的）、`CTL` 悬空（=全速转）。**认线靠板上丝印，别靠颜色。**

> ⚠️ **三个"静默杀手"**——都不报错，只表现为"什么都没发生"：
>
> | 坑 | 后果 | 规避 |
> |---|---|---|
> | 以 `-u ubuntu` 跑 | ubuntu 不在 `video` 组 → `uvc_open:Access denied` / `open camera, ret: -82` | **必须用 root**（命令里不要加 `-u ubuntu`） |
> | 按路径直接执行脚本 | 脚本没有 x 权限 → `Permission denied` | **必须写 `bash <脚本>`** |
> | 日志写到 root 属主的旧文件 | 重定向在跑脚本前就失败，`-d` 把错误吞掉 | 用 `/tmp/ascam_run.log` 时先 `docker exec armpi_pro rm -f` 清掉 |
>
> ⚠️ **第 4 个坑：重复启动会自己把自己搞死**（这一类**日志里有报错**，和前三个相反）：
> ```
> [ERROR] [UvcCamera.cpp] uvc_open:Busy                    ← 相机已被"另一个自己"占住
> [ERROR] open camera, ret: -82
> [ WARN] Shutdown request received.
> [ WARN] Reason given for shutdown: [[/ascamera_hp60c] Reason: new node registered with same name]
> ```
> 现象是「命令发出去没报错，但画面时好时坏、或者干脆没有」，而 `ps` 里能看到 **2~3 个 `ascamera_node`**。
> 本质是：后启动的节点抢不到设备，同时 ROS 又因为**同名**把先启动的那个杀掉 → 两个都废。
>
> ✅ **现在不用怕了**：`run_ascam_hp60c.sh` 已内置**幂等清理** —— 启动前会先杀掉已在跑的实例，
> **重复执行是安全的**（已实测：6 秒内连跑两次，最终仍只有 1 个节点）。
> 万一你用的是旧版脚本，先手动清场再启动：
> ```bash
> docker exec armpi_pro pkill -f '[h]p60c.launch'
> docker exec armpi_pro pkill -f '[a]scamera_node'
> ```
>
> 💡 **数进程要按名字精确匹配**：`pgrep -x ascamera_node | wc -l`。
> 用 `ps -ef | egrep ascamera_node | egrep -v egrep` 会把 grep 命令自己也算进去，**多算 1 个**，别被吓到。
>
> 📌 **`/dev/video0` 不是固定的**。实测反复开关相机后，原来的 `video0`/`video1` 会消失，
> 只剩 `video10~video31`，而相机**照样能用**（SDK 并不依赖这个编号）。
> 所以**不要拿 `/dev/video0` 在不在来判断相机好坏** —— 看 `ps` 里的进程和日志里的 `camera opened`。

### 怎么确认相机真起来了

⚠️ **这两条要在"小车的宿主系统"（②层）执行，不是在你电脑上。**

先在电脑上 `ssh pi@<小车IP>`（密码 `raspberrypi`），等提示符从
`C:\Users\Administrator>` 变成 `pi@raspberrypi:~$`，再粘贴：

```bash
ps -ef | egrep 'ascamera_node' | egrep -v egrep          # 要能看到 ascamera_node
docker exec armpi_pro bash -c 'tail -n 20 /tmp/ascam_run.log'
```

> 第 2 条里的 `docker exec` 是把命令送进③层的容器，**在②层敲**，不用自己先进容器。

**不想开会话？在电脑上一条命令也能查完**（把两个输出都带回来）：

```bat
ssh pi@<小车IP> "ps -ef | egrep ascamera_node | egrep -v egrep; docker exec armpi_pro bash -c 'tail -n 20 /tmp/ascam_run.log'"
```

**最省事的办法**：直接让 AI 查 —— 它手上有现成脚本，能一次把进程、日志、话题都验完。

日志里出现这两行才算成功：

```
[ INFO] ...: camera opened
[ INFO] ...: #camera[0x...] SN[ASC60CF22002771]'s firmware version: ...
```

紧接着的 `[stopStreaming] stop streaming` 是**正常的**（没有订阅者时的按需推流），不要据此判定失败。

## 常见问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面打不开 | 本地代理没起 | 双击 `启动控制台.bat` |
| 页面能开，但「连接」失败 | 小车 IP 变了 | `ping raspberrypi` 查新 IP |
| 连上了但没画面，角标在数重试 | 该话题没有发布者（相机节点没起） | 拉起相机节点；页面会自己重试 |
| 画面时好时坏，`ps` 里有 2~3 个 `ascamera_node` | 启动命令被执行了多次，节点互相抢 `/dev/video0`（`uvc_open:Busy` + 同名互杀） | 新版脚本已幂等，直接重跑一次即可；旧版先 `docker exec armpi_pro pkill -f '[a]scamera_node'` |
| 日志里 `/dev/video0` 找不到，但画面正常 | 设备节点编号会变，不是固定 `video0` | 正常现象，别管；以 `camera opened` + 有话题为准 |
| 想看画面但不确定链路 | — | 「画面源」先切到 `/visual_processing/image_result` 验证 |
| 「截图」按钮得到黑图 | **已知问题**：`/snapshot` 每次都是新订阅，命中 SDK 全黑的第 0 帧 | 看实时画面即可；要修需改成 canvas 抓流 |
| 深度图看不到 | web_video_server 编不了 16UC1 | 需要额外加「深度→伪彩→bgr8」节点，未做 |
