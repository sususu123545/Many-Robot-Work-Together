# ArmPi Pro 控制台运行与故障排查手册

适用对象：本仓库 `web_console/robot_console.html`、本机代理 `proxy_server(1).py`、Windows 本机隧道监督器，以及 Raspberry Pi 上的 ROS 1 Noetic 小车。

## 先看安全事项

- 排查连接、重启本机监督器或雷达前，先确认小车物理停稳，并停止自动建图。重启本机隧道会短暂断开 rosbridge。
- 控制台显示“连接断开”不等于小车已停。断线前如果小车正在自主运行或执行持续运动命令，先用实体急停/断电等现场安全方式确保停止；不要指望断网代替停车。
- rosbridge 重连后控制按钮可能重新启用。确认环境安全后再操作方向键、关节滑块或“走到该位置”。夹爪测试前清空夹爪并让手离开机构。
- 不要为排查问题绕过急停、反复发送运动命令、盲目杀掉占用 9090 的进程，或把密码、`console_supervisor.json` 发给他人。

## 一、先理解连接链路

控制台有三条不同链路，某一条正常不代表其余也正常：

| 链路 | 端点 | 用途 | 成功信号 |
|---|---|---|---|
| 浏览器页面 | Windows `http://127.0.0.1:8000/` | 加载控制台页面、本地代理视频流 | 页面能打开 |
| 控制/状态 | 浏览器 → Windows `127.0.0.1:9090` → SSH 隧道 → 小车 rosbridge `9090` | 控制底盘/机械臂，订阅 `/scan`、状态等 | 页面显示“已连接”，日志有“rosbridge 连接成功”，按钮启用 |
| 视频 | Windows 本地代理 → 小车 `:8080` | 摄像头 MJPEG | 摄像头卡片显示“画面已连接” |

本机 8000 页面能打开，只证明本地代理在运行；小车能 ping 通，只证明 IP 层可达；二者都不能单独证明 SSH、9090 或 ROS 话题正常。

## 二、正常启动

1. 在 Windows 上双击仓库中的 `web_console\启动控制台.bat`。
2. 浏览器访问 `http://127.0.0.1:8000/`。不要直接双击 `robot_console.html`，否则视频请求可能受 `file://` 跨域限制。
3. 若本机监督器正常，控制台会自动发现配置的小车并建立 SSH 隧道。等待页面显示“已连接”。通常不需要手动填写旧 IP；若页面要求输入，填写小车当前 IP，不要依赖上次的热点地址。
4. 只有 rosbridge 连接成功后，方向键、机械臂和夹爪测试才会启用。相机、雷达、SLAM 各自仍需对应小车节点发布数据。

## 三、按症状排查

### 1. `127.0.0.1:8000` 无法访问 / `ERR_CONNECTION_REFUSED`

这是 Windows 本机页面服务没有监听，不是小车 IP 问题。

- 双击 `web_console\启动控制台.bat`，等待页面打开。
- 若仍打不开，在 Windows PowerShell 检查本机端口：

```powershell
Test-NetConnection 127.0.0.1 -Port 8000
```

- `TcpTestSucceeded : False`：本机代理没有启动或启动失败。保留启动窗口中的错误信息，不要双击 HTML 文件替代。
- 端口 8000 已被其他程序占用时，不要直接结束未知进程；记录进程 PID 后先确认它是什么。

### 2. “本机隧道监督器尚未更新；请在小车静止时重启本机控制台一次”

页面每 3 秒读取 `/api/robot`。监督器心跳超过 15 秒或旧代理不支持修复状态时，会显示“待启用”，并禁用“修复连接”。这表示 Windows 本机监督状态过期，不直接说明小车端 ROS 节点损坏。

先确认小车物理停稳。然后在普通 Windows PowerShell（不要管理员权限）执行下方代码。它会先检查心跳，心跳新鲜时跳过，避免重复启动监督器：

```powershell
$statusFile = 'D:\多车协作\tools\runtime\robot_status.json'
$age = [double]::PositiveInfinity

if (Test-Path -LiteralPath $statusFile) {
  $status = Get-Content -LiteralPath $statusFile -Raw | ConvertFrom-Json
  if ($status.supervisor_heartbeat) {
    $age = [DateTimeOffset]::UtcNow.ToUnixTimeSeconds() - [double]$status.supervisor_heartbeat
  }
}

if ($age -le 15) {
  '监督器心跳正常，无需重复启动。'
} else {
  $runner = Join-Path $env:LOCALAPPDATA 'ArmPiConsole\run_console_supervisor.ps1'
  if (-not (Test-Path -LiteralPath $runner)) {
    throw "启动脚本不存在：$runner；请检查安装状态，不要猜路径或发送配置文件。"
  }
  Start-Process -FilePath powershell.exe -WindowStyle Hidden -ArgumentList @(
    '-NoProfile', '-ExecutionPolicy', 'Bypass', '-File', $runner
  )
  '已请求启动监督器；等待约 10–15 秒后查看状态。'
}
```

检查本机监督状态（只显示状态与心跳，不要复制配置密码）：

```powershell
$s = Invoke-RestMethod 'http://127.0.0.1:8000/api/robot'
$age = [Math]::Round([DateTimeOffset]::UtcNow.ToUnixTimeSeconds() - [double]$s.supervisor_heartbeat, 1)
"state=$($s.state), heartbeat_age=${age}s, repair_supported=$($s.repair_supported)"
```

正常心跳应小于 15 秒；等待自动发现期间状态可能短暂为 `searching` 或 `connecting`。若运行脚本报“拒绝访问”、心跳仍不更新，或脚本不存在，不要反复启动，也不要擅自修改执行策略/权限；保留错误并检查下文日志。安装脚本会改当前用户的开机启动项并保存本机 SSH 配置，不要为一次临时故障反复运行安装脚本。

### 3. 页面显示“连接断开”或 `ws://127.0.0.1:9090` 失败

先看页面顶部提示或 `/api/robot` 状态：

| 状态/提示 | 含义 | 下一步 |
|---|---|---|
| `searching` / “等待发现” | 监督器还没确认小车 IP | 确认电脑与小车连同一个热点、热点未启用客户端隔离；等待一个发现周期（约 12 秒）。不要强行填旧 IP 覆盖发现结果 |
| `connecting` | 正在建立隧道 | 等待 10–15 秒；仍不变再看监督器与隧道日志 |
| `ssh_retry` | 已发现小车，但 SSH 隧道失败并会重试 | 测试当前 IP 的 22 端口；检查 SSH 凭据、Pi 在线状态及日志。不要把密码写进命令、截图或聊天 |
| `port_conflict` / “端口冲突” | Windows 本机 9090 被非监督器进程占用 | 不要杀进程。用 `Get-NetTCPConnection -LocalPort 9090 -State Listen` 查看 PID，再确认所属程序；无法确认时先停止并求助 |
| `tunnel_listening` | 本机 9090 隧道已监听 | 页面应自动尝试 rosbridge；若仍失败，刷新页面一次，再查小车端 rosbridge 是否运行 |
| `repairing` / “修复中” | 已提交隧道重建请求 | 等待最多约 30 秒，不要连点。完成信息会显示 WebSocket 握手结果 |

确认当前 IP 的基础网络和 SSH 端口（Windows PowerShell）：

```powershell
Test-NetConnection <小车当前IP> -Port 22
```

`TcpTestSucceeded : True` 仅说明 SSH 端口可达。使用本地控制台时，浏览器应连本机 `127.0.0.1:9090`；手机热点可能不允许电脑直接访问小车的 9090，所以不要只用“直连小车 9090 失败”来判定小车坏了。

如果页面“修复连接”按钮可用且小车已停稳，可以点一次。此按钮只请求监督器重建本机 SSH 隧道并验证 rosbridge，不会重启小车节点；如果按钮显示“待启用”或“端口冲突”，不要反复点击。

### 4. rosbridge 已连接，但雷达点阵没有出现

先看雷达卡片角标：

- “未连接”：rosbridge 尚未连上，先处理上一节。
- “等待 `/scan` 数据”、`0 点 · 0.0 Hz`：前端已经订阅，但没有收到有效扫描；这与浏览器画布本身无关。
- 有频率但点数为 0：检查原始 `/scan` 的 `ranges`、`range_min/range_max`，再确认传感器方向/遮挡；不要先改滤波参数。

从 Windows SSH 到小车后，在树莓派宿主机终端执行以下命令（不是在 Windows PowerShell 原样执行，也不是先进入容器交互 shell）：

```bash
docker exec armpi_pro bash -lc 'source /opt/ros/noetic/setup.bash && export ROS_MASTER_URI=http://raspberrypi:11311 && rostopic info /scan'
docker exec armpi_pro bash -lc 'source /opt/ros/noetic/setup.bash && export ROS_MASTER_URI=http://raspberrypi:11311 && timeout 6 rostopic hz /scan'
```

判断：

- `rostopic info /scan` 没有 publisher：查小车宿主机的 `systemctl status ld06 --no-pager`、`ls -l /dev/ld06` 和雷达日志；雷达服务通常由 `ld06.service` 开机启动。
- 有 publisher 但 `rostopic hz` 超时：检查 LD06 USB/串口连接、服务日志与 ROS Master 连接。
- 频率约 10 Hz 且有数据，但网页仍无点：确认页面确实“已连接”，刷新一次；再对比页面是否因范围值无效而没有可画点。

只有确认小车静止且雷达节点异常时，才考虑重启雷达服务；不要把雷达服务重启当成重启整台小车。服务日志可在小车宿主机查看：

```bash
sudo systemctl status ld06 --no-pager
sudo journalctl -u ld06 -n 50 --no-pager
```

### 5. 摄像头卡片显示“加载失败”或黑屏

视频与控制使用不同端口：控制/ROS 是 9090，视频是 8080。雷达正常不代表相机节点在运行。

1. 检查页面选择的画面源是否真有图像发布者；后视相机、HP60C 深度相机 RGB 和视觉处理结果是不同话题。
2. Windows PowerShell 检查小车 8080：

```powershell
Test-NetConnection <小车当前IP> -Port 8080
```

3. 若 8080 可达但无画面，检查所选话题是否有 publisher，以及对应相机节点是否启动。相机节点不是所有安装都开机自启；小车或容器重启后可能需要按 [开机恢复手册](开机恢复.md) 启动。
4. 不要并发启动多个相机实例：相机设备可能被占用，重复同名 ROS 节点也可能互相挤掉。确认旧实例状态后再按开机恢复手册处理。
5. “截图”黑图不一定代表实时视频故障；先看实时流是否成功。

### 6. 控制按钮灰色、方向键或机械臂没有响应

- 控制按钮在 rosbridge 连接事件成功前会被禁用；先确认页面确实显示“已连接”，不是只看到 8000 页面或 `tunnel_listening`。
- 首次验证底盘前要留出空间、用最低速度，手边准备实体急停；普通方向键为持续运动，记得发停止命令/松开对应按键。失联时不要继续点击或假定小车已经停止。
- 如果方向键可用但某个外设无响应，分别核对该 ROS 话题的类型、publisher/subscriber、节点和串口/供电；不要因底盘能动就判断全部 ROS 节点正常。
- 当前夹爪通过位置滑块选择角度，只有点击“走到该位置”才会发布目标。滑动滑块本身不驱动舵机；手指远离夹爪，空载小步测试，接近机械行程端点立即停止。
- 若 `/r_joint_controller/state` 的 goal/current 已变化而实体舵机不动，问题可能在舵机管理器、总线/供电或机械卡滞；停止重复发送命令，检查驱动链路。

### 7. IMU/状态监控显示 `--`

控制台当前状态卡订阅的是 `/ros_robot_controller/imu_raw`。独立 BMI270 节点若发布 `/bmi270/imu_raw`，即使该话题有数据，当前这个 UI 字段也不会自动显示它；这是话题名不一致，不应仅凭 UI 的 `--` 判断 IMU 硬件损坏。先用 `rostopic info`/`rostopic hz` 确认发布话题，再决定是否做话题映射或调整 UI。

## 四、日志位置与求助时提供的信息

不要先清空网页“日志”卡片。排查时记录时间、当前热点/小车 IP（如愿意提供）、页面顶部状态文字、出现故障的卡片和最后几条浏览器日志。必要时查看：

- `D:\多车协作\tools\runtime\console_supervisor.log`
- `D:\多车协作\tools\runtime\tunnel.log`
- `D:\多车协作\tools\runtime\proxy.log`
- `%LOCALAPPDATA%\ArmPiConsole\runner.log`
- 小车端：`sudo journalctl -u ld06 -n 50 --no-pager`（仅排查雷达时）

分享前检查并遮盖密码、令牌、SSH 配置内容；不要发送 `console_supervisor.json`。请保留错误上下文和时间，不要只截取最后一行。

## 五、哪些现象不代表控制台故障

- `/map` 没有发布者：SLAM/建图节点可能尚未由用户启动；控制台在线与否是另一回事。
- 画面黑而 `/scan` 正常：优先查 8080、相机话题和相机节点，不要重启雷达。
- Windows 能 ping 小车但控制台断开：ping 不验证 22/9090 或 ROS；按端口、监督器状态逐段检查。
- IP 变化后旧地址失效：先使用监督器的 MAC 自动发现与当前状态，不要不断尝试旧 IP。

## 相关文件

- `web_console/启动控制台.bat`：启动本机网页代理并打开控制台。
- `web_console/robot_console.html`：前端订阅、控制和雷达/地图显示。
- `web_console/proxy_server(1).py`：本机 8000 页面与视频代理、监督器状态 API。
- `tools/console_supervisor.py`：动态发现小车并管理本机 SSH 隧道。

- `docs/开机恢复.md`：小车开机后相机、雷达的补充恢复步骤。
