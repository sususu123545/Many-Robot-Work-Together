# 本地视觉模型接入

控制台地址：`http://127.0.0.1:8000/`。相机区域内的“模型识别”连接到
本机配置的模型服务，API 地址示例为 `http://<模型主机>:8080/v1`。

## 使用

1. 等待“画面在线”和“模型在线”。
2. 输入观察问题，例如“找出红色小球，描述它在画面中的位置”。
3. 点击“识别当前画面”。页面保留本次画面缩略图、画面时间、回答和耗时。

相机视频、雷达和模型推理独立更新。不会自动持续请求模型，也不会执行模型回答。
这是视觉观察接入，尚未接入目标三维定位、底盘规划或机械臂动作。

## 配置及实现

- 本地 `web_console/model_config.json`：模型接口、超时及回答长度；该文件可能含私有网络地址，不提交到仓库。`model` 为空时读取服务当前加载的模型。
- `web_console/vision_bridge.py`：标准库实现的图片请求和异步任务；不依赖 ROS，不包含运动接口。
- `POST /api/vision/analyze`：接收当前 JPEG、画面时间及问题，返回任务 ID。
- `GET /api/vision/jobs/<id>`：读取任务状态、回答、耗时和图像 SHA-256。
- `GET /api/model`：模型在线及图片能力状态，缓存 15 秒。

相机图像与结果只在进程内存中短暂保留，不写入模型配置或工作区文件。
最多保存 12 条任务，一次只允许一个模型请求。入口限制本机同源请求、图片大小及画面新鲜度。
模型不可达、超时或无回答时会显示错误，用户可以重试。

## 验证

离线检查：`tools/test_sensor_console.js`、`tools/test_vision_bridge.py`。

2026-11-02 实测：浏览器提交 640×480 的当前相机画面，模型返回
“红色小球位于画面中下方偏左的位置，在白色地面上，靠近黑色线条标记的区域内。”
该次模型请求耗时 2.12 秒；同一期间视频与雷达继续更新。
这一次结果只验证了图片请求及回答链路，不代表目标定位或抓取精度已通过验收。
