# 机械臂几何标定方案（2026-11-05）

> 目的：一次把「FK 报告的工具点」「真实指尖」「两指中心的抓取点」三者的关系定死。
> 在此之前，所有 `dz` / `TOOL_OFFSET` 都是从错误模型上反推的数字，调不通是必然的。

---

## 1. 要解决的问题

同一次抓取尝试里，两个观测给出了**方向相反**的结论：

```
FK    : 工具点 y = 0.2128，球 y = 0.178     → 球在夹爪【后方】35 mm
图像  : 球在夹爪【前方】约 80 mm（315 px x 0.26 mm/px）
偏差  : 11 cm，且方向相反
```

这不能用"补偿不准"解释。要么是**像素尺度算错了**，要么是**FK 的参考点根本不是夹爪的物理位置**。

**先证伪第一种可能，再动几何。** 因为像素尺度错了会让所有图像测量一起偏，而它最容易验证。

---

## 2. 第一步：校准像素尺度（30 分钟，不动机器人）

图像里的距离全部依赖 `mm/px`，而我一直在用"球直径 135 px = 35 mm"反推。球的边缘是模糊的，±10 px 就是 ±7% 误差；如果实际是 100 px，那 80 mm 会变成 108 mm。

### 做法

1. 在桌面平铺一张 **A4 纸（210 x 297 mm）**，或任何尺寸已知的硬纸板，用胶带固定
2. 把臂移到 A4 纸正上方约 30 cm（`search_home` 姿态即可）
3. 拍一张，用下列脚本量纸的像素宽度

```bash
python3 - <<'EOF'
import urllib.request
from io import BytesIO
from PIL import Image
url = 'http://127.0.0.1:19099/snapshot?topic=/rear_camera/image_raw&type=ros_compressed'
img = Image.open(BytesIO(urllib.request.urlopen(url, timeout=15).read())).convert('RGB')
img.save('artifacts/a4_scale.png')
print('saved', img.size)
EOF
```

4. 人工在图上看清纸的左右边界像素坐标 `x1`、`x2`（A4 长边 297 mm），算

```
mm_per_px = 297 / (x2 - x1)
```

5. **同时**用球的直径独立算一次，两个结果对比：
   - 一致（差 <5%）→ 像素尺度可信，问题在几何模型，进第 3 步
   - 差很多 → 之前的图像测量全部作废，用新尺度重算，再判断是否需要第 3 步

### 判据

| 结果 | 结论 | 下一步 |
|---|---|---|
| 两种尺度差 <5% | 尺度可信 | 做第 3 步的三点标定 |
| 差 >15% | 尺度错了 | 用 A4 尺度重算 80 mm 那个读数，可能不需要动几何 |

---

## 3. 第二步：三点法标定（如第 2 步判定几何模型有问题）

需要定出三个点各自的位置，都用**同一时刻的同一位姿**测量，避免姿态变化引入误差。

### 3.1 采样位姿

选 4 个位姿，`j1` 固定在 500（正前方），只改 `j2/j3/j4`，让工具点高度从高到低分布：

| 位姿 | j2 | j3 | j4 | 用途 |
|---|---|---|---|---|
| P1 | 694 | 910 | 200 | 高处，视野宽 |
| P2 | 600 | 900 | 250 | |
| P3 | 500 | 880 | 320 | |
| P4 | 400 | 860 | 400 | 低处，接近抓取姿态 |

每个位姿执行：

```bash
python3 - <<'EOF'
import sys, json
sys.path.insert(0, 'tools')
import grasp_sequence as gs
from rosbridge_client import Rosbridge

bridge = Rosbridge('127.0.0.1', 19091, timeout=12)
ticks = gs.read_ticks(bridge)
pose = gs.forward_tool_pose_raw(ticks)
print(json.dumps({
    'ticks': ticks,
    'tool_xyz': [round(v, 5) for v in pose['translation_m']],
    'rotation': [[round(v, 5) for v in row] for row in pose['rotation_matrix']],
}, ensure_ascii=False))
bridge.close()
EOF
```

**同时**拍一张图保存（文件名带上位姿编号）。

### 3.2 从每张图里读出指尖位置

在 A4 纸（或带网格的垫子）作为参照的坐标系里，读出两个指尖落点的像素坐标。这是唯一需要人工的部分——因为指尖是黑色、纸是白色，肉眼分辨比算法可靠。

记下每个位姿下：
- `tip_L_px`, `tip_R_px`（两指最前端点在画面中的坐标）
- 用第 2 步的 `mm_per_px` 换算成以纸为参照的平面坐标

### 3.3 拟合

对每个位姿，我们有：

```
FK 工具点  : (x_fk, y_fk, z_fk)
图像指尖   : (x_img, y_img)  在纸平面上
```

在纸平面上把 `FK 的工具点投影` 和 `图像指尖位置` 画在一起，看四条记录是否呈现**一致的平移关系**：

- **四条记录的 (图像 - FK) 偏移都相同** → 是常量偏置，直接加补偿即可（这是我原以为的情况）
- **偏移随姿态变化** → 偏置在工具坐标系里，需要按 `R_tool` 变换
- **偏移随高度剧烈变化甚至改方向** → 说明 `forward_tool_pose_raw` 的参考点与视觉系统的帧定义不同源，需要查 URDF 里 `grasping_frame` 与相机光心 `camera_optical_frame` 的相对变换

## 4. 第三步：只验一个数，别一次改一堆

无论上面得出哪种结论，**下一次抓取只改一个参数**，其余保持不动：

1. 球放在 `y = 0.24 m`（已验证可达）
2. 只用 `dz = 0.000`，`j1 = 500`
3. 记录三件事：工具点坐标、闭爪后 `r_joint`、球是否被推动（前后位置差）
4. 如果 `r_joint` 停在 420 以下 → 成功，把这个 `dz` 固定
5. 如果夹空且球被推动 >20 mm → 说明**水平没对准**，回头看第 3.3 的拟合
6. 如果夹空但球**没动** → 说明**高度不够**，`dz` 再降 3 mm 重试

这个"球动没动"的判据很有用：它把"水平错"和"垂直错"分开了，而我今天一直没利用它。
