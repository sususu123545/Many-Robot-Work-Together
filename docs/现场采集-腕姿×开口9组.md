# 现场采集：3 腕角 × 3 开口 = 9 组

对应仿真组的要求（2026-11-23）。工具：`tools/capture_pose_sweep.py`（30 项测试）。

---

## 0. 这一步要解决什么

仿真组做同姿态像素对比后得到：

| 投影条件 | 夹指上缘偏差 | 轮廓 IoU |
| --- | --- | --- |
| 当前 Gazebo 相机 | 高 137 px | 0.00 |
| 仅换真机鱼眼内参 | 高 94–95 px | 0.37 |
| 鱼眼内参 + 实测 TF | 低 8–13 px | 0.57 |

残差还剩 8–13 px，但**只有一个姿态、夹爪开口零变化**，分不清是"腕姿相关"还是"几何/裁切相关"。
这次采集就是为了把这两个因素分开。

## 1. 现场准备

| 项 | 要求 |
| --- | --- |
| 小车 | 上电、核心容器 `armpi_ros2_native` 运行、`/joint_states` 有数据 |
| 隧道 | `python tools/ssh_tunnel.py --host 100.102.57.19`（19091） |
| 棋盘格 / 标记板 | 位置固定、格长已知，**三个腕角都能拍到** |
| 游标卡尺 | 每组都要量两指内侧实际接触部位的距离 |
| 球 | 按需移开，避免 joint4 摆动时碰到；或保留但确认净空 |

⚠️ **先确认净空**：joint4 会摆 ±15°（±62 tick）。要确认这段摆动范围内
夹爪不会碰到地面、球、线缆。

---

## 2. 确定 θ₀

把 joint4 摆到**已经验证过净空的抓前姿态**，读出当前 tick：

```bash
python tools/capture_pose_sweep.py plan --theta0-tick <当前joint4 tick> \
  --span-deg 15 --openings 30,40,48 --out plan.json
```

以 206 为例，会生成：

```
idx   angle    joint4    target mm
1     minus    144       48
2     minus    144       40
3     minus    144       30
4     centre   206       48
5     centre   206       40
6     centre   206       30
7     plus     268       48
8     plus     268       40
9     plus     268       30
```

跨度 29.8°（15° = 62.5 tick，取整 62）。
若某一端被现场净空限制，把 `--span-deg` 调小，并在记录里写明实际跨度。

---

## 3. 执行采集

```bash
python tools/capture_pose_sweep.py run \
  --plan plan.json --out-dir capture_20261124 --yes
```

每组会：

1. 重新锁运动闸门 → 单独把 joint4 移到目标 tick（单条命令 ≤100 tick）；
2. 问你要 r_joint 的 tick（**这个值脚本不知道，必须现场试**）→ 下发 → 等 3.0 s 稳定；
3. 抓 3 帧，每帧都配同刻六轴 + `arm_base → rear_camera` TF，**超 50 ms 的帧自动丢弃重试**
   （最多 6 次尝试）；
4. 问卡尺读数。若与目标差 >2 mm，会问你是否换 tick 重做该组。

### 关于 50 ms 这个指标

臂状态（`/arm_controller/status`）来自 `arm_node.py:99` 的 **0.5 s 定时器 → 2 Hz**，
图像约 **12.7 Hz**（周期 79 ms）。所以最接近的那一帧天然可能有几十毫秒偏差，
**单次尝试不一定达标**。脚本的做法是逐帧打分、多次重试、把实际偏差写进记录，
达不到就标 `skew_ok: false`，不会假装通过。

如果 9 组里有几组反复达不到 50 ms，有两个选择：
- 接受更大的偏差，但在分析时把偏差当不确定度带进去（臂是静止的，读数值仍有效）；
- 或先把臂节点的轮询定时器提速——但会与命令争串口总线，属于另一个改动，需要单独评估。

---

## 4. 采集完必查

```bash
python tools/capture_pose_sweep.py report --dir capture_20261124
```

会打印：
- 实际达到的 joint4 三个值和台阶、跨度（度）
- 实测开口集合
- **每一组没达标的项**（帧偏差超限 / 缺卡尺读数 / 缺 r_joint tick）

`clean: true` 才说明 9 组都可用。

## 6. 顺手能一起补的两件事

这次会话同时能解决之前挂着的两项，不必单独再跑：

- **夹爪开口曲线**：9 组已经覆盖 3 个开口 × 3 个腕角；若想要更密的曲线，
  在每个腕角多停 2–3 个 tick 档即可（脚本按组交互，随时可以多采）。
- **红球直径**：用卡尺量一次当前那个球，记进任意一组的备注。

## 7. 已知限制（必须告知对方）

- 现有历史数据里 **joint4 只有 5.5° 跨度、r_joint 恒为 247**，所以"开口与腕姿的
  交互影响"这一项，历史数据完全答不了，只能靠这次新采。
- 本工具**未在真机上验证过**。第一次跑建议：先把 `--frames 1 --attempts 2` 跑一组试水，
  确认帧能正常落盘、偏差数值合理，再跑全 9 组。
- 夹指在图像底边有裁切（历史帧就是这样）。若这次仍被裁，需要在采集时把 joint4
  往回收一点，或换更广的腕姿——但那会改变已确认的 θ₀，要先和对方确认。
