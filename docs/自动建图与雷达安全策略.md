# 自动建图与雷达安全策略

## 功能

网页的「开始自动建图」会发送 `/auto_mapping/cmd: start`。车端按下面的顺序工作：

1. 启动当前选择的 SLAM 引擎。
2. 确认 `/map` 和 `/scan` 已经有数据。
3. 优先从 `/map` 选择有已知自由通道的前沿点，以低速朝目标移动；无可达前沿时才回退到沿墙巡航。
4. 回到起点附近后停止运动，保留 SLAM 供用户保存地图。

节点启动后是待命状态，不会因为开机或连接网页而自动运动。

## 避障逻辑

`wall_follow.py` 的运动状态包括：

- `EXPLORE`：从栅格地图采样前沿方向，只接受车体膨胀后仍处于已知自由空间的直线路径；到达目标后重新选点。它是局部直线前沿选择器，不等同于完整 A*/Nav2 全局规划器。
- `FOLLOW`：当前沿没有可直达候选时的低速沿墙兜底，并用小幅横移修正墙距。
- `WAIT_OBSTACLE`：遇到人员或障碍先停车观察。
- `TURN`：障碍持续存在超过等待时间后，只向雷达确认更空旷的一侧转。
- `RECOVER`：只用于疑似卡死；倒退前必须确认后方距离足够。
- `ESCAPE`：同一片区域停留过久且无地图前沿时，才尝试局部脱离；必须由位姿确认实际移动达到目标距离，否则超时停车并报告，不会把计时结束当成脱困成功。
- `WAIT_MAP` / `WAIT_SCAN`：地图、定位 TF 或雷达数据不可靠时停车等待。
- `PAUSED_RECOVERY`：没有安全前沿/脱离路线或脱离未成功时停车并等待人工检查。

默认安全参数：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `cruise_speed` | 25 mm/s | 自动建图巡航速度 |
| `strafe_max` | 6 mm/s | 正常沿墙横移上限，减少麦轮打滑 |
| `prefer_turning` | true | 墙距偏差较大时优先原地转向 |
| `wall_turn_threshold` | 0.15 m | 超过此墙距误差就转向修正 |
| `wall_turn_rate` | 0.10 rad/s | 墙距修正转速 |
| `front_slow_dist` | 0.70 m | 开始减速距离 |
| `obstacle_pause_dist` | 0.34 m | 前方先停车观察距离 |
| `obstacle_clear_dist` | 0.50 m | 前方恢复通行距离 |
| `front_turn_dist` | 0.40 m | 前方转向判定阈值（先停车确认障碍） |
| `front_clear_dist` | 0.55 m | 转向结束所需前方距离 |
| `turn_clear_dist` | 0.40 m | 候选转向侧及其前侧需满足的空隙 |
| `turn_stop_dist` | 0.32 m | 转向过程路径被占用时停车，独立于准入阈值 |
| `estop_dist` | 0.30 m | 前方硬停车距离 |
| `side_pause_dist` | 0.25 m | 侧方动态障碍停车距离 |
| `side_estop_dist` | 0.22 m | 侧方硬停车距离 |
| `obstacle_clear_secs` | 1.0 s | 连续安全多久才恢复 |
| `turn_rate` | 0.20 rad/s | 原地低速转向 |
| `area_dwell_secs` | 30 s | 同一片区域最长驻留时间 |
| `area_dwell_radius` | 0.60 m | 判定为同一片区域的位姿半径 |
| `frontier_clearance_radius` | 0.25 m | 地图规划通道的车体外接圆半径（30×25cm 车体半对角线约 0.196m，再留约 5cm） |
| `area_escape_progress` | 0.45 m | 脱离必须由位姿测得的最小位移 |
| `area_escape_timeout` | 35 s | 未达脱离位移时停车报告 |
| `area_escape_min_clear` | 0.55 m | 直行方向被视为开阔的最低距离 |

10 cm 不作为运行距离；它仅用于判断车体自射的过滤下限。因为雷达安装在车体上方，10 cm 已经几乎没有刹车和定位余量。

以上距离均为雷达测距，不是车壳到障碍的净空。该配置用于 25 mm/s 低速建图；
降低的是提前停车和转向准入距离，前向 0.30 m、侧向 0.22 m 及转向路径约 0.36 m
的近障停车保护保留。首次遇到前方/侧方障碍即停止输出运动，连续确认后进入等待，
不能越过等待直接转向。两个转向候选只有都达到准入距离时才使用沿墙偏好。

## 雷达滤波

滤波只作用于巡航控制，不作用于安全急停：

- 空间中值滤波：去掉 LD06 的单点毛刺。
- 时间 EMA：让墙面距离和横移控制稳定。
- 新出现的近障碍直接采用原始近距离，不等待 EMA 慢慢下降。
- 硬停车使用原始 `/scan` 点，滤波不能把障碍“滤没”。

参数在 `car_setup/auto_mapping.yaml`：

- `spatial_filter_radius`：空间中值半径，默认 `1`。
- `ema_alpha`：时间滤波灵敏度，默认 `0.35`；越大响应越快。
- `sector_percentile`：扇区低百分位，默认 `10`；用于抑制孤立毛刺。
- `filter_enabled`：需要排查雷达时可设为 `false`。

## 上车部署

把以下文件复制到容器 `/home/ubuntu/`：

- `wall_follow.py`
- `frontier_planner.py`
- `auto_mapping_control.py`
- `auto_mapping.yaml`
- `run_auto_mapping.sh`

把 `auto-mapping.service` 安装到宿主机 `/etc/systemd/system/`，然后：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now auto-mapping.service
```

检查待命节点：

```bash
docker exec armpi_pro bash -lc \
  'source /opt/ros/noetic/setup.bash; export ROS_MASTER_URI=http://raspberrypi:11311; rostopic echo -n 1 /auto_mapping/status'
```

必须先确认车周围无人、急停可用，再发送：

```bash
rostopic pub -1 /auto_mapping/cmd std_msgs/String "data: start"
```

停止时发送：

```bash
rostopic pub -1 /auto_mapping/cmd std_msgs/String "data: stop"
```

## 验收顺序

1. `enable_motion: false` 做干运行，确认状态和 `/scan` 扇区数据。
2. 空旷地面低速直行，确认遇到人腿/纸箱会进入 `WAIT_OBSTACLE`。
3. 障碍移开至前方至少 0.65 m 后连续观察 1 秒，确认自动恢复。
4. 固定箱体挡路超过 2.5 秒，确认只向达到 0.50 m 准入距离的一侧转。
5. 最后才用 `slam_toolbox` 走一圈，返回起点后保存地图。

2D 雷达只能看到扫描平面，无法可靠识别透明物体、悬空物体和低于雷达高度的物体。自动避障不是替代现场急停，第一次实车验收必须有人在旁边看护。
