## 本次部署

增加独立 `armpi-ros2-lidar.service`，只运行 LD06 与回环 rosbridge 9091。
容器只映射 `/dev/ld06`，不映射控制板串口、电机 I2C 或 IMU。
镜像沿用已固定的 `stage-4xhjqf`，没有替换机械臂驱动镜像。

任一传感器服务节点退出后，结束该独立容器；runner 把非人工退出视为失败，
包括 ROS2 launch 的退出码 0，systemd 在 5 秒后重试。
重新创建容器时重新映射 USB 设备，检查串口占用与 9091 冲突。
不会杀掉其他串口使用者，也不会恢复整车或解除任何急停/运动锁定。

独立服务与 `armpi-ros2.service` 互斥，不能同时接管同一雷达。
本次没有修改原整车保护或开机配置，独立服务没有启用开机自启动。
恢复整车或改变开机策略需要另行处理机械臂安全故障。

自动恢复容器使用 `--rm`，仅自动清理以后新建的临时传感器容器；
日志写入系统 journald，避免断流重试无限堆积容器。此前诊断容器保留。

## 手工维护（SSH 登录小车后）

```bash
systemctl status armpi-ros2-lidar --no-pager
journalctl -u armpi-ros2-lidar -n 40 --no-pager
journalctl CONTAINER_TAG=armpi-ros2-lidar -n 40 --no-pager
```

如只需重启独立雷达和桥接、且整车核心已经停用：

```bash
sudo systemctl restart armpi-ros2-lidar
```

会短暂中断 9091 数据，不启动机械臂/底盘。不要同时启动旧 ROS1 雷达服务。
单独恢复雷达不代表整车自动建图、避障或机械臂已修复。
