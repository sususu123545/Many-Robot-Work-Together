# Isaac Sim 4.5 到 MATRiX 的机器狗开发方案

## 赛事约束

机器狗全自主组要求出发后无实时人工输入，感知、定位、规划和控制均由机载系统完成。重点任务是爬木架、桩阵绕越、叠木越障、碎石与楼梯、连续跳圈，以及跌倒自恢复。方案依据赛事技术文件制定。

## 控制分层

```text
相机 / 深度 / 激光雷达 / IMU
              |
              v
Isaac Sim 中训练的地形判断与局部规划策略
              |
              v
高层运动指令：forward / lateral / yaw / action
              |
              v
MATRiX 官方运动控制器
              |
              v
步态、平衡、足端落点、关节和电机
```

官方控制器不需要导出权重。训练策略只负责“现在该往哪里走、走多快、何时停下或切换动作”，官方策略继续负责腿部运动和稳定性。

## 当前接口事实

当前机器上的 ROS 2 只有 `/rosout` 和 `/parameter_events`，MATRiX 没有提供可直接订阅的 ROS 2 控制话题。MATRiX v1.1.2 的可用运动入口是 UDP JSON，默认本机 `127.0.0.1:7447`，建议 20Hz 持续发送；超过约 0.5 秒没有刷新会失效。

核心映射为：

```text
LY -> forward
LX -> -lateral
RX -> -yaw
```

因此部署时使用一个机载桥接节点：读取 Isaac/策略输出，做限幅、心跳和急停看门狗，再转成 MATRiX UDP 指令。仿真和实机使用同一高层指令格式，便于先回放验证。

## 开发顺序

1. 在 Isaac Sim 4.5 中先做平地、坡道、台阶、碎石、木架和桩阵场景。
2. 先训练局部规划和速度决策，不训练关节力矩。
3. 用固定的官方运动控制器在 MATRiX 仿真中回放 `forward/lateral/yaw`。
4. 加入 0.5 秒心跳、速度限幅、失联刹停和跌倒状态机。
5. 将同一桥接节点移到 ZSL1 机载电脑，现场只下发任务开始/结束，不使用外部实时遥控。

## 当前阻塞点

Isaac Sim 4.5 已在 RTX 3090 + 580.178.04 驱动下启动；其 ROS 2 桥接因未加载 Humble 环境而报错。第一阶段可以直接使用内置 Python/UDP 做回放，随后再补齐 ROS 2 传感器桥接。MATRiX 当前使用内置运动控制，实机接入前必须在官方允许的本机控制入口上做低速、急停和失联测试。
